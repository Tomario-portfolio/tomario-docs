# コスト設計書

## 1. 基本方針

dev・staging環境はできる限りコストをゼロに近づける設計とする。
コストのかかるリソースは「使うときだけ起動する」運用で対応する（cost-stop/start）。
RDSインスタンスクラスやWAF Web ACLなど、"停止"ができないが"作成・削除"は可能なリソースについても、同じ発想で「使う時だけ作る」運用に寄せることでコストを抑える（詳細は各項目参照）。

## 2. リソース別コスト方針

### 無料で使えるリソース

| リソース | 理由 |
|---------|------|
| VPC / サブネット / IGW / ルートテーブル | 完全無料 |
| セキュリティグループ | 完全無料 |
| IAM | 完全無料 |
| CloudWatch メトリクス・アラーム（10個まで） | 無料枠内 |
| SNS | 100万通知/月まで無料 |
| GitHub Actions | パブリックリポジトリは無制限無料 |
| S3 VPCエンドポイント（Gateway型） | 完全無料 |
| CloudTrail（管理イベント） | 完全無料 |
| AWS Budgets（2つまで） | 完全無料 |
| Cost Anomaly Detection | 完全無料 |

### コストが発生するリソースと対策

| リソース | 通常コスト | 対策 | 対策後のコスト |
|---------|----------|------|-------------|
| ALB | ~$17/月 | 作業時以外は削除する | $0 |
| ECS Fargate | ~$9/月（0.25vCPU / 0.5GB） | 作業時以外はタスク数0にする | $0 |
| VPCエンドポイント（Interface型 × 4） | ~$29/月 | 作業時以外は削除する（cost-stop対象） | $0 |
| RDS | ~$15/月（無料枠終了後） | 作業時以外は停止する | ~$0.23/月（ストレージのみ） |
| Secrets Manager | ~$0.80/月 | DB認証情報・Flask SECRET_KEYの2件を管理 | ~$0.80/月 |
| GuardDuty | ~$1〜3/月 | 30日無料試用後に課金開始 | ~$0.50/月（低トラフィック） |
| VPC Flow Logs | ~$0.02/月 | CloudWatch Logsに7日保持 | ~$0.02/月 |

### 「停止」できないが「作成・削除」で代替するリソース

## 3. 運用コスト試算

| 状況 | 月額目安 |
|------|---------|
| 普段（ALB削除・ECSタスク0・VPCエンドポイント削除・RDS停止） | ~$1.55（GuardDuty ~$0.50 + VPC Flow Logs ~$0.02 追加） |
| 作業中・デモ時（ALB作成・ECS起動・VPCエンドポイント作成・RDS起動） | ~$55/月相当（時間課金） |

### production環境のコスト試算

production環境も**リリース前はdev/staging同様のcost-stop運用**とする（ALB削除・ECSタスク0・VPCエンドポイント削除・RDS停止）。リリース（面接活動期間に入るタイミング）で常時稼働に切り替える。

| 状況 | 月額目安 |
|------|---------|
| 普段（リリース前・cost-stop中） | ~$1.8/月（RDS Multi-AZのストレージ ~$0.46/月 + GuardDuty ~$1〜3/月 + VPC Flow Logs ~$0.02/月） |
| 稼働時（作業確認・負荷テストなど） | 時間課金。stagingの~$55/月相当よりやや高め（CPU/メモリ2倍・Multi-AZのため） |
| 常時稼働（リリース後） | ~$115/月（内訳は下表） |

#### 常時稼働（リリース後）の内訳

| リソース | 月額目安 | 備考 |
|---------|---------|------|
| ALB | ~$17/月 | リリース後は常時起動（削除保護も有効化） |
| ECS Fargate（0.5vCPU/1GB×2タスク baseline、Graviton） | ~$36/月 | stagingの2倍スペック（[availability](availability-high-level-spec.md)参照）。オートスケール時（最大4タスク）はさらに増加 |
| VPCエンドポイント（Interface×4） | ~$29/月 | リリース後は常時起動（NAT Gatewayを使わないため必須） |
| RDS（db.t3.micro、Multi-AZ） | ~$30/月 | Single-AZの約2倍（[database](database-high-level-spec.md)参照） |
| Secrets Manager | ~$0.80/月 | DB認証情報・SECRET_KEYの2件 |
| GuardDuty | ~$1〜3/月 | prodアカウント単独で有効化（nonprodのsharedとは独立）。リリース前後問わず常時稼働（停止不可のサービスのため） |
| CloudTrail（管理イベント） | $0 | |
| VPC Flow Logs（S3出力） | ~$0.02/月 | |
| **常時稼働ベースライン合計** | **~$115/月** | |

以下はコストと運用の兼ね合いから、常時稼働に切り替えた後も**面接が近いタイミングだけ**有効化する運用とする（WAF/Security Hubはstop/startという状態が無く時間按分課金のため、cost-stopと同じ発想で使う時だけ作成・削除する）。

| リソース | 常時起動した場合の月額目安 | 運用方針 |
|---------|-------------------------|---------|
| AWS WAF（CloudFront・ALB用Web ACL） | ~$14〜16/月 | 面接期間のみ作成、それ以外は削除（`todo.md`のSEC-5） |
| Security Hub + AWS Config | ~$3〜5/月 | 面接期間のみ有効化、それ以外は無効化（`todo.md`のSEC-6） |

面接期間だけの短期間有効化であれば、時間按分課金により実際の課金額はごく小さく抑えられる見込み。

## 4. コスト管理の運用方法

### ALBの管理
- ALBは「停止」ができないため、不要時は削除する
- GitHub Actionsの手動ワークフローで削除・作成を管理する

### ECS Fargateの管理
- ECSサービスのdesired_countを0にしてタスクを停止する
- cost-stopで0に変更、cost-startで1に戻す

### VPCエンドポイントの管理
- Interface型VPCエンドポイント（ECR API / ECR DKR / CloudWatch Logs / Secrets Manager）はcost-stop時に削除する
- cost-startで再作成する（terraform apply）

### RDSの管理
- RDSは停止中もストレージ料金が発生する（~$0.23/月）
- **注意：AWSの仕様により7日後に自動で再起動される**
- 毎週手動で停止し直す運用とする

### コスト監視
- AWS Budgets：月間予算$10を設定し、80%・100%到達時にメール通知する
- Cost Anomaly Detection：サービス別の異常な費用増加を検知し、$5以上の異常を翌日メール通知する

### productionの運用方針

**リリース前：** ALB・ECS・VPCエンドポイント・RDSはdev/stagingと同じcost-stop対象とする。ALBの削除保護（`enable_deletion_protection`）は`false`のままにしておく必要がある（`true`のままだとcost-stopのALB削除が失敗するため）。

**リリース時：** 常時稼働へ切り替える。ALB削除保護をtrueにする、cost-stop/startのワークフロー対象からproductionを外す、といった変更が必要（Terraformコード上は該当箇所にコメントで両方の値を用意しておき、切り替え時にコメントを入れ替える運用とする。詳細は`backend-environment-design.md`参照）。

WAF・Security Hub+AWS Configは、常時稼働に切り替えた後も面接が近いタイミングだけterraform applyで作成・有効化し、それ以外は削除・無効化する運用とする。
Budgetsの予算額はdev/staging合算の$10とは別に$130/月を設定する（常時稼働時の想定コスト~$115/月に運用の余裕を見た閾値。リリース前はcost-stopで実支出がごく小さいため、閾値超過＝設定ミスや消し忘れのサインとして機能する）。
